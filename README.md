# LAB_ — 计算机基础造轮子项目集

一个从零动手构建计算机系统核心组件的学习项目集。用 C / C++ 从底层原理出发，亲手实现内存分配器、Shell、文件系统、Web 服务器、关系型数据库，在造轮子的过程中建立对系统软件的深度理解。

## 项目总览

| 项目 | 语言 | 核心主题 | 代码量级 |
|------|------|----------|----------|
| [Allocator](#allocator--内存分配器) | C | 内存管理 / 堆 / 链表 | ~150 行 |
| [Shell](#shell--命令行解释器) | C | 进程 / 信号 / 管道 / 终端 | ~500 行 |
| [documents system + web](#documents-system--web--文件系统--web-服务器) | C | 文件系统 / HTTP / 并发 / 网络 | ~2000+ 行 |
| [database](#database--关系型数据库) | C++ | SQL解析 / B+树 / 存储引擎 / 缓存 | 分层架构，多模块 |

## Allocator · 内存分配器

**位置：** `Allocator/`

一个用户态内存分配器的最小实现，提供 `my_malloc` / `my_free` / `my_realloc` 三个核心接口，直接用 `sbrk` 向操作系统申请堆空间，用双向空闲链表管理内存。

### 项目架构

```
 用户调用
    │
    ├── my_malloc()   ── 遍历空闲链表 → first-fit → 分裂块 → 不够则 sbrk 扩容
    ├── my_free()     ── 归还到空闲链表 → 向后合并相邻空闲块
    └── my_realloc()  ── 原地扩容(合并后够) / 新分配+拷贝+释放(不够)

 底层结构
    ┌────────────────────────────────────────────┐
    │  block_header (16B 对齐)  │  用户数据区    │
    │  size | free | pre | next │               │
    └────────────────────────────────────────────┘
```

### 能学到的知识与技能

- **内存对齐**：用位运算实现 16 字节对齐（`ALIGN` 宏），理解为什么需要对齐以及对齐如何减少内部碎片
- **堆扩展机制**：`sbrk()` 系统调用的工作方式，program break 的概念
- **空闲链表 (Free List)**：双向链表的增删操作，first-fit 分配策略
- **块分裂与合并**：分配时 split_block 减少内部碎片，释放时 merge_block 减少外部碎片
- **内存块头设计**：在用户指针前隐藏元数据（size、free 状态、前后指针），用户完全无感知

## Shell · 命令行解释器

**位置：** `Shell/`

一个功能完备的迷你 Shell，支持内置命令、外部命令执行、单管道、后台运行、终端原始模式输入、信号处理。

### 项目架构

```
  main() 主循环
    │
    ├── print_prompt()         打印彩色提示符 (当前路径)
    ├── getinput()             原始终端模式输入，支持退格，自行回显
    ├── deal_with_input()      词法拆分 → Command 结构体 (token数组 / pipe标记 / bg标记)
    │
    ├── 内置命令: exit / cd (支持 cd - 切换上一目录, OLDPWD 环境变量)
    │
    ├── execute_command()      单命令执行
    │   ├── fork() 创建子进程
    │   ├── 子进程: execvp() 执行 + 信号恢复默认
    │   └── 父进程: 前台 waitpid 阻塞 / 后台加入 bg_pids 数组
    │
    └── execute_pipe_command() 管道执行
        ├── pipe() 创建管道
        ├── fork 两次: 左进程 stdout → pipe写端, 右进程 stdin → pipe读端
        └── 父进程关闭 pipe 两端，等待/后台管理两个子进程

  信号层
    ├── SIGCHLD: handle_child()  非阻塞回收僵尸进程 (waitpid WNOHANG)
    ├── SIGINT:  handle_int()    shell 忽略，交给前台子进程
    ├── SIGTSTP/SIGQUIT:         直接忽略
    └── 后台进程竞态保护:  fork 前阻塞 SIGCHLD，记录 pid 后再解锁
```

### 能学到的知识与技能

- **进程模型**：`fork()` / `execvp()` / `waitpid()` 的经典组合，理解父子进程关系
- **Unix 信号**：`sigaction` 注册信号处理器，`SIGCHLD` 回收僵尸进程，信号阻塞防止竞态
- **管道与 I/O 重定向**：`pipe()` + `dup2()` 实现进程间通信，理解文件描述符的本质
- **终端编程**：`termios` 原始模式（关闭 ICANON/ECHO），手动处理退格与回显
- **后台作业管理**：`&` 语法、`bg_pids` 数组维护、`clean_up_processes` 定期清理
- **Shell 解析**：命令拆分、管道识别、后台标记，理解交互式命令行的工作原理

## documents system + web · 文件系统 + Web 服务器

**位置：** `documents system + web/`

两个模块组合的综合性项目：底层是一个类 ext2 的简易文件系统（运行在磁盘镜像文件上），上层是一个支持静态资源、CGI、线程池、epoll I/O 多路复用的 HTTP 服务器，并实现了基于 Cookie/Session 的用户登录系统。

### 项目架构

```
┌─────────────────────────────────────────────────────────────┐
│                        Web 服务器层                          │
│  web2.c                                                     │
│  ┌──────────┐   ┌──────────┐   ┌─────────────────────────┐ │
│  │ epoll    │   │ 线程池    │   │ HTTP 请求处理            │ │
│  │ I/O 复用 │──▶│ 任务队列  │──▶│  静态文件 (content-type)│ │
│  │          │   │ 4 worker │   │  CGI / 登录 / Session    │ │
│  └──────────┘   └──────────┘   └───────────┬─────────────┘ │
│                                            │                 │
└────────────────────────────────────────────┼─────────────────┘
                                             │
┌────────────────────────────────────────────┼─────────────────┐
│                        文件系统层           │                 │
│  interface.h  →  achieve.h → help.h        │                 │
│  (对外API)        (业务逻辑)   (底层结构)    ▼                 │
│                                                               │
│  磁盘镜像 (disk.img, 1MB, 2048 块 × 512B)                     │
│  ┌──────┬──────┬──────┬──────────┬────────────────────┐      │
│  │Super │inode │block │ inode    │   data blocks      │      │
│  │block │ map  │ map  │ table    │   (文件/目录内容)   │      │
│  │  1   │  1   │  1   │  8块=64  │                    │      │
│  └──────┴──────┴──────┴──────────┴────────────────────┘      │
└───────────────────────────────────────────────────────────────┘
```

#### 文件系统层结构

| 层次 | 模块 | 职责 |
|------|------|------|
| 接口层 | `interface.h` | `fs_mount` / `fs_mkdir` / `fs_create_file` / `fs_read_file` / `fs_write_file` 等对外 API |
| 实现层 | `achieve.c` | 目录操作、文件读写、权限管理等业务逻辑的具体实现 |
| 基础层 | `help.h` + 对应实现 | 超级块、inode、位图、块分配、块读写、索引指针（直接/间接/双重间接） |

**核心数据结构：**
- **Super_block**：魔数、总块数、各类区域块数、空闲计数、根 inode
- **Inode**：类型(文件/目录)、大小、创建/修改时间、6个直接指针 + 一级间接 + 二级间接
- **Director_entry**：目录项 = inode 号 + 文件名（28字节）
- **FScontext**：挂载上下文，缓存 super_block / inodemap / bitmap / inodetable

#### Web 服务器层结构

| 模块 | 文件 | 功能 |
|------|------|------|
| 服务器主循环 | `web2.c` | epoll 事件循环、线程池初始化、优雅关闭 |
| 连接处理 | `achieve.c` | HTTP 请求解析、响应发送、静态文件、CGI、登录/登出 |
| 会话管理 | `achieve.c` | 基于 Cookie 的 Session，`/dev/urandom` 生成 token，24h 过期 |
| 文件系统接口 | `interface.h` | 将用户文件操作映射到虚拟文件系统 |

### 能学到的知识与技能

**文件系统方向：**
- **磁盘布局设计**：超级块 → inode 位图 → 块位图 → inode 表 → 数据区，理解 ext2/类 Unix 文件系统的经典布局
- **inode 原理**：inode 是什么、为什么需要、多级索引指针（直接/间接/双重间接）如何支持大文件
- **位图管理**：用位图管理空闲块与空闲 inode，位操作宏的编写
- **目录实现**：目录本质上是特殊文件，内容是目录项数组
- **虚拟磁盘**：用普通文件模拟磁盘镜像，理解块读写的底层抽象

**Web / 网络方向：**
- **HTTP 协议**：请求行/头部/体的解析，响应状态码与 Content-Type 处理
- **Socket 编程**：`socket` / `bind` / `listen` / `accept` 全套流程，TCP 选项（SO_REUSEADDR / SO_KEEPALIVE / TCP_NODELAY）
- **I/O 多路复用**：`epoll` 的工作原理，单线程管理大量连接
- **线程池**：任务队列 + 条件变量 + 互斥锁的经典实现，生产者-消费者模型
- **CGI 协议**：通过 fork+exec 调用外部程序处理动态请求
- **会话管理**：Cookie / Session 的工作机制，token 生成与过期策略
- **信号处理**：SIGINT 优雅关闭、SIGPIPE 防止崩溃
- **并发安全**：多线程环境下的共享资源保护（session 互斥锁）

## database · 关系型数据库

**位置：** `database/`

一个从零构建的简化关系型数据库，覆盖 SQL 解析、执行器、存储引擎、B+ 树索引、页缓存管理等完整层次。支持 `create table` / `insert` / `select` / `delete` / `update` / `drop table` / `show tables` 等基本 SQL 语句，where 谓词支持主键等值条件。

### 项目架构

```
  Main.cpp  (入口: 初始化 Pager → SymbolTable → Storage → REPL 循环)
    │
    ▼
┌───────────────┐
│   Parse 层    │  parse.cpp / tokenize.cpp / sense.cpp
│  词法→语法→语义│  tokenize() → parse_command() → valid 检测
└───────┬───────┘
        │ SQL Command 对象
        ▼
┌───────────────┐
│  Executor 层  │  executor.cpp / executor.hpp
│   执行调度     │  根据命令类型分发到 Storage 层接口
└───────┬───────┘
        │
        ▼
┌───────────────────────────────────┐
│         Storage 层                │  storage.cpp / storage.hpp
│   语义检查 · 序列化 · 系统表管理   │  系统表存表元信息 / Row 序列化反序列化
└───────────────┬───────────────────┘
                │ 页读写请求
                ▼
┌───────────────────────────────────┐
│         Pager 层                  │  pager.cpp / pager.hpp
│    页缓存 · LRU 淘汰 · 哈希索引    │  哈希表缓存 + LRU 链表 + 主页面表分配
└───────────────┬───────────────────┘
                │
                ▼
┌───────────────────────────────────┐
│        B+ Tree 层                 │  B+Tree/Btree.cpp
│     插入 · 删除 · 查找 · 分裂合并  │  StackPath 记录搜索路径用于回溯分裂/合并
└───────────────────────────────────┘
        │
        ▼
  磁盘文件 (sql.db)
```

#### 各模块详解

| 模块 | 关键文件 | 核心职责 | 关键结构/算法 |
|------|----------|----------|--------------|
| 词法分析 | `Parse/tokenize.cpp` | 将 SQL 字符串切分为 token 流 | 关键字识别、字符串字面量、数值解析 |
| 语法/语义解析 | `Parse/parse.cpp` `Parse/sense.cpp` | 识别命令类型、校验表名列名类型 | 递归下降式解析、系统表元数据校验 |
| 执行器 | `Execute/executor.cpp` | 调度执行各类 SQL 命令 | 命令分发模式 |
| 存储引擎 | `Storage_engine/storage.cpp` | 表管理、行序列化/反序列化、系统表 | RowHeader + 列式存储布局、系统页存元信息 |
| 页管理器 | `Storage_engine/pager.cpp` | 页缓存、LRU 淘汰、表页面分配 | 哈希表快速查找 + 双向链表 LRU |
| B+ 树索引 | `Storage_engine/B+Tree/Btree.cpp` | 有序索引的插入/删除/查找 | 节点分裂、合并、借用、StackPath 回溯 |
| 工具层 | `Help/Serialize/` `Help/Cast/` `Help/Error/` `Help/Show/` | 序列化、类型转换、错误处理、结果展示 | 可复用工具函数 |

**存储格式：**
- B+ 树叶子节点中存放行数据：`[RowHeader][int:val][size][string:val]...`，用偏移数组定位列
- 系统页存储表元信息：表名、列数、各列名与类型
- 页大小固定，B+ 树节点按页存储

### 能学到的知识与技能

- **SQL 解析原理**：词法分析 → 语法分析 → 语义检查的经典三段式，递归下降解析器的写法
- **数据库分层架构**：Parse / Executor / Storage / Pager / B+Tree 各层职责与边界
- **B+ 树实现**：节点结构、分裂与合并算法、StackPath 回溯法处理叶子到根的级联操作
- **存储引擎设计**：行存储格式、序列化/反序列化、系统表（元数据自举）
- **页缓存与 LRU**：哈希表 + 双向链表实现 O(1) 的 LRU 缓存淘汰
- **C++ 工程实践**：`std::variant` 做结果/错误返回、`unique_ptr` 内存管理、模块分离编译
- **错误处理体系**：自定义 Error 类，各层统一的错误传递机制

## 学习路径建议

按依赖关系从易到难：

```
Allocator (内存管理基础)
    ↓
Shell (进程/信号/管道 → 系统编程基础)
    ↓
documents system + web (文件系统 + 网络并发 → 系统综合)
    ↓
database (数据库内核 → 最高难度，综合运用全部知识)
```

每个项目都可以先读头文件了解接口，再读实现理解细节，最后动手修改/扩展来验证理解。
